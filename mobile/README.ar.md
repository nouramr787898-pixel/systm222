# سورس Flutter لتطبيق إحكام المسار — Android وiOS

**اللغة: Dart. إطار العمل: Flutter.** سورس واحد يُبنى لتطبيق Android وتطبيق iPhone. الاسم المقترح: «إحكام المسار»، والإصدار الأولي: `0.1.0+1`.

هذه حزمة سورس أولية للمراجعة والبناء بواسطة مطوّر النشر، وليست APK/AAB/IPA موقّعًا أو نسخة منشورة. لا تحتوي الحزمة مشروع React Native أو TypeScript أو Expo.

## حالة التحقق الحالية

- سورس Dart قُرئت صياغته بمحلل Dart نحوي محلي؛ هذا **لا يعادل** `flutter analyze` أو نجاح البناء.
- نجح اختبار Python لإعدادات Android/iOS على ملفات منصات مؤقتة، بما فيها الأذونات والتوقيع وKeychain وإعادة التشغيل دون تكرار الإعدادات.
- نجحت 70 حالة اختبار للخادم والجلسات والصلاحيات ودخول الموقع والهاتف والإشعارات بإرسال وهمي وإعداد المنصتين. هذا تحقق للخادم المشترك، وليس لاختبارات واجهة Flutter.
- كُتبت اختبارات `flutter_test` للقواعد الأساسية؛ **لم تُنفّذ** بعد.
- تعذرت تهيئة Flutter SDK في بيئة التسليم: شبكة البيئة رفضت تنزيل Dart من المصدر الرسمي `storage.googleapis.com`. لم تُعطّل TLS أو آليات التحقق، ولم تُستخدم نسخة مجهولة المصدر.
- لم يُنفّذ `flutter pub get`، ولا `flutter analyze`، ولا بناء Android/iOS، ولا تجربة هاتف فعلي. لا يُقدَّم السورس كإصدار جاهز للمراجعة في المتجر قبل إتمام هذه الخطوات.

## المحتويات

- `lib/main.dart`: واجهات عربية للموظف والمشرف والإدارة، مع اختيار الشركة، والطلبات، والبصمة، والإشعارات داخل التطبيق، ومساعد الشركة.
- `lib/api.dart`: HTTPS، وجلسة Bearer، وتخزين رمز الجلسة في Keychain/Keystore، ومعالجة الانتهاء، ومنع تحويل الطلب الموثق إلى عنوان آخر.
- `lib/push.dart`: تسجيل جهاز FCM وتجديد الرمز والإذن وفتح الإشعارات وإيقافها.
- `PUSH-SETUP.ar.md`: إعداد خدمة الإرسال في Firebase وApple والخادم.
- `lib/domain.dart`: تنسيق الساعة بنظام 12 ساعة، والمدد بدقة ثانية، والتواريخ وتجهيز الطلبات وترشيح الشركة.
- `test/domain_test.dart`: اختبارات Flutter للقواعد السابقة.
- `tool/bootstrap.py`: يستخدم `flutter create` الرسمي لتوليد مضيفي Android وiOS، ثم يضيف اسم التطبيق والأذونات وKeychain وإعداد التوقيع.
- `assets/logo.png`: شعار إحكام.
- `STORE-LISTING.ar.md`: الاسم والوصف المختصر والتفصيلي للمراجعة قبل النشر.

مجلدا Android وiOS يُولّدان بالأداة الرسمية عبر الخطوة التالية؛ لم تُدرج ملفات منصات ناقصة أو يُدّعَ أنها بُنيت. المعرّف المبدئي لكل منصة `com.ehkam.portal`؛ يجب التأكد من ملكيته وتوافره ومطابقته مع تطبيقات حسابات النشر قبل اعتماده.

## التشغيل وإكمال فحص السورس

المتطلبات: Flutter stable **3.41 أو أحدث مع Dart 3.11 أو أحدث**، وPython 3 لتجهيز المضيفين. إصدارات المكتبات المباشرة مثبتة في `pubspec.yaml` وفق إصدارات pub.dev الرسمية؛ يولد أول `flutter pub get` ملف `pubspec.lock` الذي يجب الاحتفاظ به بعد التحقق.

داخل مجلد السورس `mobile`:

```sh
python3 tool/bootstrap.py --android-id com.yourcompany.yourapp --ios-id com.yourcompany.yourapp

dart format lib test
flutter analyze
flutter test
flutter run --dart-define=EHKAM_API_URL=https://YOUR-ACTUAL-SYSTEM-HOST
```

استبدل معرّفي المثال بالقيم النهائية التي يراجعها صاحب الحساب. لا تُستخدم الأمثلة لحجز تطبيقات فعلية. لا تُحذف بيانات الموقع أو تُعاد تهيئة قاعدة بياناته أثناء إعداد الهاتف.

الأمر `bootstrap.py` يولّد ملفات المنصتين دون استبدال ملفات Dart الموجودة، ثم يضبط:

- أذونات الموقع أثناء الاستخدام والإنترنت فقط؛ لا يضيف إذن تتبع خلفي.
- اسم التطبيق ومنع Android Auto Backup لحماية تخزين الجلسة.
- السماح بـHTTP في Debug فقط للتجارب المحلية؛ إصدار Release يقبل HTTPS في عميل API أيضًا.
- معرّفات الحزم، وموقع MainActivity الموافق لها.
- وصف صلاحية الموقع وKeychain entitlements على iOS.
- توقيع Release في Android بمفتاح المسؤول؛ يرفض استخدام توقيع Debug للنشر.

يرفض السكربت استبدال إعداد توقيع مخصص موجود؛ راجع إعدادات منصتك يدويًا في هذه الحالة. راجع إعدادات geolocator_apple بحسب طريقة دمج المكتبات في إصدار Flutter المستخدم؛ عند CocoaPods يمكن اتباع إعداد `BYPASS_PERMISSION_LOCATION_ALWAYS=1` الموثق بالمكتبة عند الاقتصار على الموقع أثناء الاستخدام.

### تجربة محلية ببيانات مصطنعة

من جذر مستودع السيستم:

```sh
python3 -B demo.py --data-dir /tmp/ehkam-flutter-demo --port 8765
```

ومن مجلد الهاتف على Android Emulator:

```sh
flutter run --dart-define=EHKAM_API_URL=http://10.0.2.2:8765
```

على هاتف حقيقي استخدم عنوان الشبكة المحلية لجهاز التطوير. لا تستخدم بيانات موظفين حقيقية للتجربة. إصدار Release يرفض HTTP. عنوان الموقع الافتراضي في السورس هو `https://systemehkam.online` المذكور في المحادثة؛ يجب أن يتحقق مطوّر الرفع من عنوان HTTPS الفعلي وأن `/api/mobile/login` نُشر عليه قبل اختبار الدخول.

## تكامل الخادم والموقع

الخادم الموجود على الموقع **Python 3 + SQLite**، وواجهة الموقع **JavaScript / HTML / CSS**. التطبيق يستخدم نفس الحسابات والبيانات والصلاحيات؛ لا توجد قاعدة هاتف تكتب فوق قاعدة الإنتاج.

يلزم نشر تغييرات الخادم المرفقة بالسورس الأصلي:

- `POST /api/mobile/login` يفحص كلمة المرور والدور وMFA وحدود المحاولات ويرجع رمز جلسة للهاتف.
- الهاتف يرسل `Authorization: Bearer ...` إلى واجهات السيستم الحالية.
- تنطبق مهلة الخمول والانتهاء المطلق وسحب الجلسات مثل الموقع.
- `POST /api/logout` يلغي جلسة هذا الجهاز.
- دخول الموقع الحالي بكوكي HttpOnly باقٍ؛ لم يُحوّل الموقع إلى طريقة جلسات الهاتف.

عند تسليم الهاتف منفردًا، يحتوي مجلد `backend` داخل حزمة التسليم على patch لتغييرات Python المطلوبة. ليس هذا المجلد نسخة مستقلة من خادم السيستم؛ يجب تطبيقه على نسخة المستودع المطابقة أو استخدام commit التسليم من فرع `codex/professional-hr-upgrade`، وعدم تطبيق patch مكرر.

## نطاق النسخة الأولية

تسجيل الدخول وMFA، الحساب والرصيد، موظفو الشركات، الطلبات وتفاصيلها ومرفقاتها، إنشاء الأنواع المدعومة، قبول/رفض الطلبات المسندة وفق الصلاحيات، البصمة بموقع العمل المحدد، مدد الحضور، إشعارات داخل التطبيق، ومساعد الشركة. وظائف الرواتب والتوظيف والسياسات والإجراءات الإدارية المتقدمة الكاملة تظل في الموقع ويُتاح فتحها من التطبيق.

أُضيف كود Push للهاتف وربط طابور الخادم، لكن تشغيله الفعلي يحتاج إعداد Firebase وAPNs واختبار هاتف حقيقي وفق [تعليمات الإشعارات](PUSH-SETUP.ar.md). لا تتضمن النسخة بصمة دون إنترنت أو تتبع موقع في الخلفية. إظهار زر في الهاتف لا يمنح صلاحية؛ القرار النهائي للخادم. قبل النشر يلزم اختبار جميع الأدوار ومسارات الرفض والرصيد والمرفقات وأذونات الموقع على أجهزة فعلية.

## ملفات Google Play وApp Store

بعد نجاح التحليل والاختبارات والتجربة واعتماد الأيقونة وصور المتجر وروابط الخصوصية والدعم:

- **Android:** أنشئ upload keystore لدى مسؤول النشر. انسخ `tool/key.properties.example` إلى `android/key.properties` وأدخل القيم محليًا بشكل آمن. لا تُرفع المفاتيح أو كلمات مرورها إلى GitHub.
- **iOS:** اختر Apple Team والتوقيع وBundle ID الصحيح من Xcode على Mac أو من بيئة بناء macOS موثوقة. راجع Keychain والموقع وبيانات المتجر.

```sh
flutter build appbundle --release --dart-define=EHKAM_API_URL=https://YOUR-ACTUAL-SYSTEM-HOST
flutter build ipa --release --dart-define=EHKAM_API_URL=https://YOUR-ACTUAL-SYSTEM-HOST
```

الأول ينتج AAB لـGoogle Play، والثاني IPA بعد توقيع iOS الصحيح. لا يمكن بناء IPA على Linux. قبول المتاجر ليس مضمونًا بنجاح التجميع؛ يراجع صاحب الحساب بيانات النشر والخصوصية وحساب المراجعة التجريبي قبل الإرسال. لا تحتوي الحزمة شهادات توقيع أو حسابات أو كلمات مرور متاجر.
