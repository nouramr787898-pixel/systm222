## ما أصبح موجودًا

التسليم **مشروع Flutter واحد**، وليس مشروعَي سورس منفصلين. يحتوي المجلد الجذري `ehkam_mobile` عند فك ZIP على `lib` و`android` و`ios` و`assets` و`test` و`tool` و`pubspec.yaml` و`pubspec.lock` و`.metadata`.

- وُلّدت ملفات Android وiOS داخل التطبيق الحالي بواسطة `flutter create` الرسمي، ثم طُبقت إعدادات التطبيق وFirebase. لم يُستبدل كود التطبيق بمشروع Counter أو تطبيق آخر.
- ملفات Android تشمل Gradle وGradle wrapper كاملًا وManifest وMainActivity والموارد وملف Firebase. الحد الأدنى API 24 وفق اعتماد Firebase Messaging الحالي.
- ملفات iOS تشمل Xcode project وworkspace وRunner وAppDelegate وSceneDelegate وموارد الواجهة وملفات Flutter وPodfile الرسمي بعد ضبط iOS 15، وملف Firebase وentitlements.
- ملفات Firebase الأصلية محفوظة دون تغيير بايتاتها، لمشروع `ehkam-almasar` ومعرف `com.ehkam.portal`.
- ملف الاعتماديات المقفل `pubspec.lock` ناتج عن حل الاعتماديات فعليًا، وليس ملفًا مكتوبًا يدويًا.
- أضيف اختبار فعلي لشاشة الدخول العربية واتجاهها والانتقال إلى الاستعادة، واختبار يمنع حفظ كلمة مرور قصيرة قبل التحقق من الرمز ويقبل كلمة صحيحة من ثمانية أحرف. استُبدل اختبار Counter الذي ولّده Flutter لهذا السبب.
- نُسق كود Dart بأداة Dart الرسمية، وأزيل import غير لازم، ووثقت الاستدعاءات المتوافقة الحالية لرموز تسجيل FCM عند مواضعها.

المجلدات التي تولدها الأدوات مثل build وPods و.dart_tool والمسارات المحلية والمفاتيح وقواعد بيانات الموظفين ليست جزءًا من سورس التطبيق، وتُستبعد عمدًا. تُنشأ ملفات المسارات المحلية وتسجيل المكتبات على جهاز المطور بواسطة Flutter وCocoaPods.

## بيئة الفحص ومصدر الأدوات

استُخدمت صورة Cirrus Labs المعزولة:

```text
ghcr.io/cirruslabs/flutter:3.41.0
sha256:ccca87bba2643d52913878f969e44e45bc3b528ef7ea88ca3f510f2aa5dec79f
```

Flutter ‏3.41.0 وDart ‏3.11.0. مراجعة Flutter داخلها `44a626f4f0027bc38a46dc68aed5964b05a83c18`، وطُوبقت مع وسم `3.41.0` في مستودع Flutter الرسمي. صورة البناء من Cirrus Labs، وليست صورة رسمية صادرة من Flutter. استُخدم وكيل الشبكة المدار وشهادة الثقة الخاصة بالجلسة مع إبقاء التحقق من TLS مفعّلًا؛ لم تُدرج إعدادات الوكيل أو شهادته في السورس.

## ما يحتاجه المطور بعد استلام المشروع

1. افتح المجلد الذي يحتوي `pubspec.yaml`، أو ادخل `mobile` عند استنساخ مستودع النظام. نفّذ `flutter pub get` ثم فحص Firebase والتحليل والاختبارات حسب README.
2. على جهاز يستطيع تنزيل اعتماديات Flutter وGradle كاملة، ابنِ Android Debug وجربه على جهاز فعلي. على Mac جهز Xcode وCocoaPods وابنِ iOS وجربه على iPhone.
3. اضبط عنوان الخادم الفعلي بـ`EHKAM_API_URL`. التطبيق يتصل بخادم النظام؛ لا يحمل قاعدة بيانات الموقع داخله. حسابات المراجعة التجريبية في خادم منفصل، ولا تنشأ تلقائيًا في الإنتاج أو داخل التطبيق.
4. راجع Apple Team وملف التهيئة وبيئة APNs، واربط مفتاح APNs في Firebase، وجهز هوية إرسال الخادم. ملفا إعداد العميل ليسا مفاتيح إرسال للخادم أو APNs.
5. اختبر Push فعليًا في المقدمة والخلفية وعند عدم فتح التطبيق، واختبر النقر وتسجيل الخروج وتبديل الحساب، ثم باقي إجراءات الطلبات والبصمة والصلاحيات على أجهزة حقيقية.
6. أكمل توقيع Android وApple واعتماد أيقونات المتجر والخصوصية وبيانات المراجعة قبل إصدار AAB وIPA. أيقونات المنصتين المولدة تحتاج اعتماد الشكل النهائي؛ لا يعد اكتمال ملفات السورس موافقة للنشر النهائي.

## GitHub ودعوة المطور

ملفات المشروع وتسليمه الموحد تُرفع إلى نفس فرع العمل. محاولة استخدام GitHub API لإدارة دعوة المطور تعذرت: اتصال `api.github.com` مرفوض من وكيل الشبكة برسالة Tunnel 403 Forbidden. الرفع عبر Git متاح، لكنه لا يمنح قناة لإرسال دعوة إدارية. **لم تُرسل الدعوة، ولا يوجد تأكيد وصول بريد دعوة.**

يمكن لصاحب المستودع إتمام الدعوة من Settings ثم Collaborators أو إعدادات الوصول، واختيار Add people ثم البريد الذي حدده في المحادثة، أو توفير تكامل GitHub مخوّل ومتاح لهذه العملية. صلاحية القراءة العامة بالرابط، إن كانت متاحة، تختلف عن دعوة صلاحية التعديل.

## الخلاصة المعتمدة للتسليم

ملفات مشروع Flutter موحدة وموجودة للمنصتين، والتحليل والاختبارات المذكورة ناجحة. لا يُقدّم ZIP باعتباره تطبيقين موقّعين أو إعلانًا بنجاح بناء Android/iOS أو تسليم إشعارات حقيقية. التقارير القديمة التي تصف المضيفين بأنهما غير موجودين هي تقارير تاريخية سابقة لاستكمالهما.
