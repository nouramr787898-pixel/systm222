# تسليم 0.1.1+2 — حالة الإصدار وخطوات الإكمال

تم تجهيز سورس Flutter مشترك لحزمتَي Android وiPhone، مع إشعارات FCM، والطلبات والبصمة، واستعادة كلمة المرور داخل التطبيق، وسياسة كلمات مرور 8–128 حرفًا دون اشتراط أرقام أو رموز.

**حالة الإصدار: سورس للمراجعة والبناء؛ ليس نسخة موقعة جاهزة للنشر.** لم يعمل Flutter SDK هنا لأن تنزيل Dart من `storage.googleapis.com` رفضه وكيل شبكة البيئة بـ403. البيئة Linux، ولا تحتوي Xcode أو هوية Apple أو مفاتيح توقيع Android. لا توجد نتيجة بناء AAB/IPA، ولا نتيجة `flutter analyze`/`flutter test` أو تجربة على أجهزة فعلية. فحص الصياغة لا يحل محلها.

الحسابات التجريبية التي طلبها صاحب المشروع موجودة في حزمة خادم المراجعة المنفصلة، ولم تُضف لقاعدة بيانات الموقع الحقيقي. تم التحقق محليًا من الدخول بالحسابات الثلاثة عبر مساري الموقع والهاتف، وفحص سلامة SQLite ومفاتيحها الأجنبية. لا توجد بيانات موظفين حقيقية في حزمة المراجعة.

## ترتيب تجهيز نسخة المتجر

1. افتح مشروع السورس على جهاز عليه Flutter stable 3.41+/Dart 3.11+، وعلى Mac مع Xcode لبناء iOS.
2. اعتمد معرفَي التطبيق النهائيين مع صاحب حساب المتاجر، ثم نفّذ `tool/bootstrap.py` وفق README لتوليد مشروعَي Android وiOS الرسميين.
3. ملفا عميل Firebase الحالي أُضيفا، لكن توليد المضيفين وإعداد APNs وهوية إرسال الخادم والتوقيع ما زالت مطلوبة. راجع `PUSH-SETUP.ar.md`. الإشعارات مبرمجة، لكنها لم تُسلّم إلى هاتف فعلي هنا.
4. شغّل خادم المراجعة المحلي من الحزمة المنفصلة. لمراجعي المتاجر أو هاتف بعيد، انشره على بيئة اختبار HTTPS مستقلة خلف reverse proxy مناسب، واستخدم نطاقه في `EHKAM_API_URL`. بيانات المراجعة لن تعمل إذا بنيت التطبيق على نطاق الموقع الحقيقي الذي لا يحتوي هذه الحسابات.
5. نفّذ `dart format lib test` و`flutter analyze` و`flutter test`، وثبّت `pubspec.lock` بعد نجاح حل الاعتماديات، ثم ابنِ وجرب على Android وiPhone فعليين، بما في ذلك الإشعارات والبصمة والاستعادة والصلاحيات وعرض RTL والمرفقات.
6. أضف توقيع Android وApple المملوك لصاحب الحساب؛ لا تستخدم توقيع debug للنشر. ابنِ AAB وIPA وفق README، ثم أكمل الأيقونات وصور المتاجر وروابط الخصوصية والدعم وإفصاحات جمع البيانات وبيانات وصول المراجعين قبل إرسال النسختين.

اسم التطبيق المقترح ووصفه في `STORE-LISTING.ar.md`. الحسابات التجريبية وملف بياناتها مخصصة لخادم المراجعة؛ لا تضع كلمة مرور أو قاعدة SQLite ضمن assets التطبيق أو الكود المرفوع إلى GitHub.
